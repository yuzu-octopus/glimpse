# Repository Guidelines

## Project Overview
Glimpse is a glance-inspired self-hosted dashboard: a **Bun + Vite + React 19 + Astryx** SPA with server-side fetching. Widgets (see README → Widgets for the catalogue and per-widget options) render into a **12-col bento grid** (`pages → columns → widgets` from YAML, plus `tiling: collage` via a single `place()` module). One dark theme — the `astryx-dracula` kit, a runtime dependency. PWA shell via `vite-plugin-pwa`. Config lives in `config.yml`; secrets stay server-side.

Read the README before touching anything here. It is the authority on what a widget is called, which options it takes, and what the user-facing behaviour is. This file is the authority on how the code is arranged and the rules you must not break.

## Architecture & Data Flow
```
config.yml → shared/config.ts (Zod discriminated union) → server/config.ts (watch, $include, ${ENV})
  → server/api.ts buildPagePayload | streamPagePayload → TtlCache + Singleflight (stale-on-error)
  → GET /api/page/:slug?stream (NDJSON: $skeleton line first, then per-widget chunks in settle order)
  → client/hooks/usePageData.ts (SWR pageCache + shape-overlay reconcile, urgent per-chunk renders)
  → client/pages/PageView.tsx (--col-span grid / data-span bento, memoized WidgetSlot)
  → WidgetChrome → lazy registry ensureWidgetLoaded(type) → Suspense → client/widgets/<type>/index.tsx
```
- **Shared contract:** `src/shared/` Zod schemas + wire types (`api.ts`) are imported by both sides; shared is a leaf (no runtime imports of server/client). Theme tokens are NOT here — they come from the `astryx-dracula` package.
- **Widget path:** `shared/widgets/<group>.ts` (schema + DEFAULTS + co-located PREF + SKELETON), `server/widgets/<type>.ts` (`registerWidget`), `client/widgets/<type>/index.tsx` (`registerWidgetComponent`). Typed registries join them. Shared props every widget inherits live in `shared/widgets/shared.ts`: `title`, `title-url`, `hide-header`, `cache`, `css-class`, `retries` (0–10, default 3), `show-errors` (default true), plus the bento hints `priority`/`span`/`zone`. `shared/widgets/aliases.ts` folds glance's `to-do`/`stocks` onto `todo`/`markets` before the union discriminates, at any nesting depth.
- **Widget defaults are the schema's job.** A schema `limit` default applies automatically (README quotes the same numbers); fetchers must not re-default. A `cache` string, when present, is the only TTL input — otherwise `getDefaultTtl(type)` picks the per-kind TTL (README → Configuration).
- **Caching:** per-widget TTL cache keyed `slug:path` (`h:i`, `w:i`, `c:col:i`); fresh hit short-circuits; on fetcher failure `getStale` serves the 24h-retained copy (stale-on-error). `Singleflight.run(key, fn)` dedupes concurrent fetches.
- **Streaming:** first NDJSON line is `{path:'$skeleton', payload:skeletonPagePayload(page)}` (full layout, all `data:null`) so cold loads paint immediately; subsequent chunks use path forms `headWidgets[i]`, `widgets[i]`, `columns[ci].widgets[wi]` — note these differ from cache-key paths. Stream `cancel()` aborts upstream fetches (`AbortSignal.any`). `?force=1` clears that slug's server cache first (explicit reload hits upstream). `streamPagePayload`'s resolved-queue drops a rejected task silently (`p.then(v => push, () => wake())`), and that branch is **unreachable in production**: `fetchWidget` catches every fetcher rejection into `payload.error` and its container recursion is `Promise.all` over `fetchWidget`, so by induction no task can reject (the only theoretical source is `serverWidgets.get` throwing on a real `Map`). Do not add a catch for it — `api.test.ts` pins the property that makes it unnecessary instead (every configured widget gets a frame, carrying its own error, at head/column/nested depth). If that test ever needs a fix, fix `fetchWidget`.
- **Client SWR:** module-level `pageCache` (30s stale, 5m GC) + inflight dedupe (identity-guarded delete); caller aborts never kill the shared fetch (internal AbortController); `fetchPage` reads the NDJSON body incrementally (`getReader()`, per-line) so chunks render as they arrive — never buffer with `res.text()`. `applyChunk` is copy-on-write for the flat `widgets[]` path (slice before assignment) so memoized consumers see new array refs; `reload(force)` clears data for instant skeleton; `reconcileWithCached` adopts skeleton layout and overlays cached payloads by index so config-shape changes appear instantly; errors surface only when there is no last-good data. **The stream closing is the boundary:** `reconcileStreamEnd` runs on both streaming exits (reader done, and the line-split fallback — not the whole-page JSON branch, which cannot be truncated) and stamps `NO_RESPONSE_ERROR` on any widget that ends the stream at `data: null` with no error, so a truncated stream fails visibly instead of shimmering forever. A widget that answers *before* the close keeps its data, a widget carrying a server error keeps that error, and `CONFIG_ONLY` types (plus the abort case, whose partial payload is cached as-is) are left untouched. Copy-on-write like `applyChunk` — containers are recursed into even though they are config-only, because their children stream inside the container's own frame.
- **Warm-up:** `server/warmup.ts` `warmCache(ctx)` builds every page through the normal cache path at boot and on config reload (`initConfig(path, onChange?)` callback), deleting all slug prefixes first so edited configs never serve stale TTL entries. Fire-and-forget, all-settled, guarded on `r.ok` for reloads, concurrency-capped at `WARMUP_CONCURRENCY`.
- **Skeletons:** `WidgetChrome` prop `skeletonShape` ('list'|'stat'|'chart'|'rows', default 'rows') from shared `SKELETON_SHAPE` map; `PageSkeleton` is delayed 250ms (`DelayedSkeleton`) so fast loads show nothing. `PageSkeleton` mirrors the ready render's column spans (explicit `span` or `resolveSpan` from `size`) + the cached `tileStyle(span)` objects, so the skeleton grid matches the real column widths.
- **Polling:** `liveKey` single tree walk → homelab types poll 1s, other LIVE_TYPES 30s, static none. The live/static TTL constants live in `shared/live.ts`; `getDefaultTtl` in `server/cache.ts` layers the per-type overrides on top.
- **Theme:** one brand, zero switching. `src/main.tsx` imports `./client/kit/icons` FIRST (side-effecting `registerIcons(draculaIconRegistry)`; the global icon registry is module state, so a later call leaves the first painted tree on core's icons), then the kit in the order that is the contract (`@astryxdesign/core/reset.css` → `astryx.css` → `astryx-dracula/tokens.css` → `astryx-dracula/theme.css` → `./index.css`); `vite.config.ts` sets `@layer reset, astryx-base, astryx-theme` so the kit's `theme.css` lands in the `astryx-theme` slot. `GlimpseThemeProvider` is a thin wrapper — `<Theme theme={astryxDraculaTheme} mode="dark">` + `LinkProvider` + the optional `custom-css-file` `<style>`. No runtime token mirroring, no `documentElement` mode patching, no `glimpse.theme.v1` / `glimpse.paint.v1`; `index.html` carries a constant Dracula `#282a36` / `#9aa1bc` first paint.

- `public/` — favicon/icon SVG, fonts (woff2 precached); `dist/` — hashed Vite build (gitignored); `glance/` — reference Go app (gitignored, never linted); `docs/research/` and `docs/superpowers/{specs,plans}` — design docs and reports

## Development Commands
```bash
bun install
cp config.example.yml config.yml
bun run dev:server   # bun --watch src/server/index.ts (:3000)
bun run dev          # vite :5173, proxies /api -> :3000 (changeOrigin)
bun run build        # tsc --noEmit && vite build -> dist/ (PWA precache ~1.1MB across ~91 files)
bun run start        # bun serves dist/ + API (:3000; GLIMPSE_PORT, GLIMPSE_CONFIG or argv[1])
bun run test         # vitest run (jsdom, globals)
bun run test:watch   # vitest watch
bun run new-widget <kebab-name>  # scaffold schema + fetcher + renderer + tests
bun run check-config [path]      # validate config (line numbers + did-you-mean)
npx react-doctor@latest  # full scan gate; glance/** ignored via doctor.config.json
```
Env: `GLIMPSE_CONFIG` (CLI arg wins > env > ./config.yml), `GLIMPSE_PORT=3000`, `GITHUB_TOKEN`/`GH_TOKEN` (GitHub widgets; falls back to `gh auth token` via `server/github-token.ts`, then unauthenticated 60 req/h), `${VAR}` interpolation in YAML. No `.env` loader (`.env*` gitignored).

## Code Conventions & Common Patterns
- **Strict TS:** `strict`, `verbatimModuleSyntax`, `ES2024/bundler`, `noEmit`, noUnusedLocals/Parameters. No `ReturnType` aliases, no inline casts (except CSSProperties custom-var objects), unconditional hooks.
- **Zod v4:** `.loose()`, `z.record()` 2 args, `.default(()=>...)`. Validate at trust boundaries; fetchers re-validate their config slice per fetch (intentional defense-in-depth — keep it). Schema defaults supply `limit`; fetchers must not re-default.
- **Naming:** kebab-case widget types, PascalCase components, `*.module.css`. `PREFERRED_SIZES[type]` is a `Pref` — `{cols, rows, resizable, priority, zone, preferredWidth, preferredHeight}` — and drives bento sizing.
- **Registries:** server `registerWidget(type, fn)` / client `registerWidgetComponent(type, comp)`; client barrel is lazy (`widgetLoaders` dynamic imports, `ensureWidgetLoaded`, per-slug idle `scheduleWidgetPreload(types)` triggered from `usePageData`). iframe/html share one chunk. A `registry-coverage` test fails listing any `WidgetType` missing a server import or client loader — silent absence is impossible.
- **Async:** `fetchWithRetry` (backoff+jitter, retryable statuses) for all remote calls; the per-widget `retries` field (0–10, default 3) is parsed by `retryOptionsFrom(cfg)` in `server/widgets/http.ts` and reaches every fetcher, so `retries: 0` means exactly one attempt. `Promise.allSettled` fan-out for feed lists; `sanitizeUrl()` in the shared `http.ts` error paths so query-string secrets never reach `payload.error` (widget-local fetches that throw their own errors must sanitize too).
- **Memo invariants (load-bearing):** streaming replaces whole widget object refs (`applyChunk` never mutates rendered payloads) — this is why `memo` on WidgetSlot/MobileColumn/BentoItem is safe; the cached `tileStyle(span)` objects mean memoized columns never see fresh refs. Don't break either.
- **Grid:** explicit 12-track desktop / 6-track ≤900px / single-column ≤600px with `grid-auto-flow: dense`; one pure `place(tiles, width)` module (`tiling.ts`) drives tiles + skeletons + samples so they can never disagree. Container queries own widget interiors.
- **WidgetChrome:** `collapseAfter >= 0` truncates behind Show more; `-1` (any negative) never collapses; `items` renders rows, `children` otherwise. `showErrors={false}` (the widget's `show-errors: false`) drops the Banner, the error text and the red chrome — the header StatusDot still reports the failure, so quiet is never invisible. Every renderer passes `showErrors={cfg['show-errors']}`.
- **State:** no global store; `useConfig` (cached Promise, failures retried) + `usePageData(slug)`; `localStorage` only for todo (`glimpse.todo.<id>`), timer (`glimpse.timer.<id>` + `.notes`), and notepad (`glimpse.notepad.<id>`). The theme persists nothing; ai-quota has no client persistence.
- **Astryx warning:** ONLY valid API reference is `node_modules/@astryxdesign/core/dist/**/*.d.ts` (`defineTheme`, `<Theme theme mode>`, Card/Banner/Text/TabList/Skeleton/SelectableCard/Dialog/Link, Button/Badge/StatusDot/ProgressBar/CheckboxInput/TextInput/IconButton/Stack/Grid). The `skill://astryx` documents an INVENTED API (ThemeProvider/createTheme/swizzle) — never "fix" code toward it. `astryx-dracula` (`^0.2.1`, MIT) is a **runtime dependency**, not a vendored copy: `astryxDraculaTheme` + `draculaIconRegistry` from the package root, `tokens.css` / `theme.css` from its subpath exports. Colors are the kit's — never add a hex or override `--color-*` in `src/index.css`; reach for a `src/client/kit/` component or a `--color-data-*` token before hand-rolling one. The kit's own `astryx-dracula.d.ts` is the only source for its token names.
- **Deliberate ignores:** react-doctor off-rules (iframe-sandbox, no-multi-comp, no-fetch-in-effect, dangerous-html-sink, set-state-after-await-in-effect, unused-export, low-supply-chain-score) are intentional; don't re-enable or code around them silently.

### Adding a widget (checklist)
0. Prefer the generator: `bun run new-widget <kebab-name>` scaffolds schema + fetcher + renderer + tests + registry lines (verify with `bun run check-config`).
1. Schema + DEFAULTS + PREF + SKELETON in `src/shared/widgets/<file>.ts` — the generator writes one file per widget; hand-written schemas group by kind (feeds.ts / keyed.ts / calendar.ts / media.ts / twitch.ts / clock.ts / …). Spread `...sharedWidgetFields` so every shared prop exists (see the shared-props list under Architecture). The real `Pref` shape is `{cols, rows, resizable, priority, zone, preferredWidth, preferredHeight}` — `span` is a shared config option, NOT a Pref field. Append the schema to `schemaEntries` in `src/shared/widgets/index.ts`.
2. Registry row in `widgetMeta` (`src/shared/widgets/index.ts`) pairing schema + pref + skeleton — `PREFERRED_SIZES` / `SKELETON_SHAPE` derive from it (derivation test fails if a union member has no row; never edit `preferredSizes.ts` by hand).
3. Data widgets: fetcher in `src/server/widgets/<name>.ts` (`registerWidget`) + import in `src/server/widgets/index.ts`. Config-only widgets (clock, bookmarks, search, todo, calendar, iframe, html, timer, notepad, group, split-column) need none — the builder yields null data, and `registry-coverage.test.ts` lists them in `CONFIG_ONLY` so the guard stays green.
4. Renderer `src/client/widgets/<name>/index.tsx` (`registerWidgetComponent`) + loader entry in `src/client/widgets/index.ts` `widgetLoaders`.
5. Tests mirroring the files (see Testing). Then `bun run check-config` and the registry-coverage guard: every `WidgetType` needs a server import (unless `CONFIG_ONLY`) and a `widgetLoaders` entry (containers excluded), and an orphan on either side fails too.
6. Update README → Widgets: the row in the data-widget table (or the config-only line), its source/notes, and the type count in Features if you added a type.

## Runtime/Tooling Preferences
- **Runtime:** Bun ≥1.3 (`Bun.serve`, `Bun.file`, `Bun.YAML`, `Bun.XML`, `bun --watch`). Node never runs the server; plain-node YAML fallback exists only for vitest.
- **Package manager:** `bun` / `bunx` (never npm/npx/node/pip). `bun.lock` is the lockfile; `trustedDependencies` covers @astryxdesign postinstall scripts.
- **Build:** Vite + `@vitejs/plugin-react`, `vite-plugin-pwa` (autoUpdate, `navigateFallbackDenylist [/^\/api\//]`), lazy widget chunks + manualChunks react/astryx/icons/react-router-dom. `/api/config` sends no-store while the SW caches it — intentional offline layering, documented in vite.config.ts.
- **Constraints:** headless shared Chromium available for browser smoke tests; `glance/**` ignored everywhere; unported glance widgets are tracked in README → Known deviations (`extension`, `calendar-legacy`; no auth/lockout).
- **Astryx CLI config:** `astryx.config.mjs` (project root) registers `astryx-dracula` in the CLI's `integrations` list, which is what makes `bunx astryx template <id> --package astryx-dracula` resolve the kit's ~43 themed pages/blocks. Keep exactly one `astryx.config.*` in the repo — two make `astryx doctor` FAIL; verify with `bunx astryx doctor` and `bunx astryx template --list`.

## Testing & QA
- **Stack:** Vitest 4 + jsdom + `@testing-library/react` + `jest-dom`, `globals:true`, `setupFiles: ./src/test/setup.ts` (localStorage polyfill, dialog shims, Bun global).
- **Conventions:** a fetcher test per data widget and a component test per renderer are the floor; a schema test is added only when a widget has rules worth pinning. Fetcher tests inject `WidgetFetchContext` (fixtures + fake fetch, zero network) — canonical template `src/server/widgets/rss.test.ts`; cross-cutting behavior in `src/server/widgets/widget-behavior.test.ts` (fake timers). Hook tests: `vi.stubGlobal('fetch')`, `vi.resetModules()` + dynamic import, `__clearCacheForTests()` between tests; NDJSON fixtures simulate `$skeleton` + chunk lines. Component tests: stub via `registerWidgetComponent` in beforeEach (delete after), or import the widget module directly — widget renderers self-register on import, so there is no preload helper to call.
- **Gates:** `bunx tsc --noEmit` clean · `bun run test` green · `npx react-doctor@latest` full scan (the `--scope changed` flag is unreliable — always full scan). Never hardcode a test count in this file; the suite grows every wave.
- **Run:** `bun run test` (CI-equivalent), `bun run test:watch` locally, `bunx tsc --noEmit` before commit.
